# π0 (2024)

*이산 토큰을 버리고 흐름(flow)으로 — 연속 action을 직접 생성하는 VLA*

Black, Brown, Driess 외 (Physical Intelligence), *π₀: A Vision-Language-Action Flow Model for General Robot Control*, 2024 (arXiv 2410.24164). 카테고리 개요는 [VLA 리뷰 허브](vla.md), 우리가 직접 재현·파인튜닝한 [OpenVLA](openvla.md), VLA라는 이름을 만든 [RT-2](rt2.md), 실습 기록 전체는 [VLA 실습 페이지](../vla.md).

이 논문은 문헌만 리뷰했다 — 아직 우리가 직접 실행하지는 않았다. 다만 RT-2(가중치 영구 비공개)와 달리 **가중치가 공개**돼 있어(`openpi`, 2025년 2월 공개) 재현 자체는 가능한 상태다 — §4 참고.

## 한 줄 요약

> PaliGemma(3B) VLM에 **flow matching으로 학습된 action expert(~300M)** 를 결합한 VLA. OpenVLA·RT-2가 action을 256-bin으로 이산화해 "다음 토큰 예측"으로 풀었던 것과 달리, π0는 무작위 노이즈에서 시작해 **ODE(상미분방정식) 적분으로 50-스텝 연속 action chunk를 한 번에** 생성한다. Open X-Embodiment와 자체 수집한 7개 로봇·68개 태스크·1만 시간 이상의 데이터로 학습했고, 세탁물 개기·테이블 정리 같은 장기·양손 조작에서 이산 토큰 기반 베이스라인(OpenVLA, Octo)을 크게 앞섰다고 보고한다.

---

## 1. 문제 — 이산 토큰이 정밀·고주파 조작을 막는다

RT-2·OpenVLA 계열은 연속 action을 차원별 256-bin으로 양자화하고, 언어 토크나이저의 저빈도 토큰을 덮어써 "action을 언어처럼" 자기회귀 디코딩한다([RT-2 리뷰](rt2.md) §2.2, [OpenVLA 리뷰](openvla.md) §2.2). 이 설계는 VLM 학습 인프라를 그대로 재사용할 수 있다는 실용적 이점이 있지만, 구조적으로 두 가지가 아프다.

1. **정밀도 손실**: 연속 7-DoF action을 256단계로 양자화하면 옷감을 집어 정렬하는 것 같은 미세 조작에서 해상도가 부족하다.
2. **속도·chunk 트레이드오프**: 자기회귀 디코딩은 토큰을 한 개씩 순차 생성한다. 여러 스텝의 action을 한 번에(action chunk) 뽑으려면 토큰 수가 그만큼 늘어나 느려지므로, 실무에서는 매 스텝(또는 몇 스텝)마다 다시 추론해야 한다 — 고주파(수십 Hz)·양손·장기 조작에는 근본적으로 불리한 구조다.

π0 저자들은 이 한계를 직접 지목한다: 셔츠 개기 같은 태스크에서 "OpenVLA는 자기회귀 이산화 아키텍처가 action chunk를 지원하지 않기 때문에 어려움을 겪는다"(원문). π0의 질문은 명확하다 — **VLM이 가진 웹 스케일 의미 일반화는 유지하면서, action을 내는 쪽만 diffusion/flow 계열의 연속·고주파·chunk 생성으로 바꾸면 어떨까?**

## 2. 방법

### 2.1 아키텍처 — 하나의 트랜스포머, 두 세트의 가중치

$$
\text{이미지, 지시문} \;\longrightarrow\; \text{VLM 백본(PaliGemma, 사전학습)} \qquad \text{상태 } q_t,\ \text{노이즈 action} \;\longrightarrow\; \text{action expert(무작위 초기화)}
$$

원문 표현으로는 "하나의 트랜스포머에 두 세트의 가중치(전문가)를 두고, 토큰마다 그중 하나로 라우팅한다"는 **mixture-of-experts** 구조다.

- **VLM 백본**: 이미지·언어 토큰은 **PaliGemma(3B, Gemma 기반)** 로 라우팅된다. VLM 사전학습 때 보지 못한 입력(상태·action)은 별도 전문가로 간다.
- **Action expert**: 로봇 고유수용감각 상태 $q_t$(선형 투영으로 트랜스포머 임베딩 차원에 매핑)와 노이즈가 섞인 action 토큰을 처리하는 **별도 가중치의 소형 트랜스포머(~300M)**. VLM과 파라미터를 공유하지 않지만, 같은 트랜스포머 안에서 attention을 공유한다.
- **어텐션 마스크**: [이미지/언어] · [상태] · [노이즈 action] 3개 블록에 대한 **블록별 causal mask** — 블록 내부는 양방향 full attention, 블록 간에는 뒤 블록이 앞 블록을 볼 수 있지만 역방향은 불가(이미지/언어는 action을 보지 못함).
- **총 파라미터**: PaliGemma 3B + action expert 300M ≈ **3.3B** — OpenVLA(7B)보다 작다.

### 2.2 Flow matching — 노이즈에서 action으로, ODE 적분

핵심은 action expert를 이산 분류가 아니라 **연속 벡터장 회귀**로 학습하는 것이다. 학습 시점에는 참 action $A_t$에 노이즈 $\epsilon$을 섞어 중간 상태 $A_t^\tau$를 만들고, 그 지점에서의 목표 벡터장 $u(A_t^\tau \mid A_t) = \epsilon - A_t$를 향하도록 action expert $v_\theta$를 회귀시킨다(원문):

$$
L^\tau(\theta) = \mathbb{E}\big[\, \lVert v_\theta(A_t^\tau, o_t) - u(A_t^\tau \mid A_t) \rVert^2 \,\big]
$$

추론 시점에는 **무작위 노이즈에서 출발**해 $\tau=0$부터 $\tau=1$까지 학습된 벡터장을 **forward Euler 적분(10 스텝, $\delta=0.1$)** 으로 따라가며 action을 생성한다. 즉 diffusion policy와 같은 계열(반복적 노이즈 제거)이되, 확산 대신 흐름(flow)의 ODE 적분을 쓴다는 점이 이름의 유래다.

이 방식의 실용적 이점은 **한 번의 적분으로 $H=50$ 스텝짜리 action chunk 전체가 나온다**는 것이다 — OpenVLA처럼 스텝마다(혹은 토큰마다) 자기회귀 디코딩을 반복할 필요가 없다. 원문이 보고하는 온보드 추론 총 시간은 **73ms**(이미지 인코딩 + 관측 처리 + 10회 flow 적분 포함) — 이 한 번의 호출로 나온 50-스텝 chunk를 **최대 50Hz**로 순차 실행하면서 다음 chunk를 백그라운드로 미리 계산하는 방식으로 고주파 제어를 실현한다. UR5e·Franka처럼 저주파 로봇은 20Hz로 낮춰 구동한다(원문).

### 2.3 학습 데이터

- **오픈 데이터**: Open X-Embodiment, Bridge V2, DROID.
- **자체(proprietary) 데이터**: **7종 로봇 구성**(단일팔 UR5e/Franka, 양팔 Trossen/ARX, 모바일 매니퓰레이터 등) × **68개 태스크**, 총 **1만 시간 이상**의 로봇 데이터(원문). 세탁물 개기, 테이블 정리(bussing), 식료품 담기, 상자 조립, 물건 회수 등 조작 난이도가 높은 태스크가 포함된다.
- 오픈 데이터와 자체 데이터를 가중 혼합해 사전학습한 뒤, 다운스트림 태스크는 소량 데이터(원문 기준 1~20시간대)로 파인튜닝한다.
- **ablation**: VLM 사전학습 없이 무작위 초기화한 소형 변형 **π0-small(470M)** 이 전체 π0보다 뚜렷이 낮은 성능을 보여, RT-2가 주장했던 "웹 스케일 VLM 사전학습이 로봇 제어로 전이된다"는 논지를 flow-matching 설계에서도 재확인한다.

### 2.4 오픈소스화 — openpi

Physical Intelligence는 2025년 2월 `openpi` 저장소(Physical-Intelligence/openpi)를 공개해 π0와, 이산 토큰화를 다시 시도한 자매 논문 **π0-FAST**(Pertsch 외, *FAST: Efficient Action Tokenization for Vision-Language-Action Models*, arXiv 2501.09747)의 가중치·추론 코드·파인튜닝 코드를 함께 배포했다. ALOHA·DROID 플랫폼용 즉시 사용 가능한 체크포인트가 포함되어 있고, 이후 Hugging Face가 PyTorch 포트(LeRobot 통합)를 추가했다. 후속작 π0.5(2025, arXiv 2504.16054)는 이번 리뷰 범위 밖이다.

## 3. 결과

원문(Figure 7/11/13)이 보고하는 정성적 패턴은 다음과 같다 — 정확한 성공률 수치는 그래프 기반이라 표로 옮기지 않고 미확인으로 남긴다.

- **Zero-shot(사전학습 직후)**: 셔츠 개기에서 π0는 "거의 완벽에 가까운" 성공률을 보인 반면, "OpenVLA는 자기회귀 이산화 아키텍처가 action chunk를 지원하지 않아" 어려움을 겪었다고 명시(원문). 테이블 정리(쉬움/어려움 변형 모두)에서도 모든 베이스라인 대비 큰 폭의 개선을 보고하며, 데이터·연산량을 베이스라인과 맞춘 "parity" 버전조차 베이스라인을 앞선다고 밝힌다.
- **파인튜닝**: 새 다운스트림 태스크에서도 π0가 대체로 우세하지만, 저자들 스스로 "가장 강력한 경쟁 모델은 해당 태스크로 처음부터(from scratch) 학습한 특화 모델"이라고 인정한다 — 일반화 모델이 항상 특화 모델을 이기는 건 아니라는 정직한 단서.
- **복합 장기 태스크**(세탁물 개기, 테이블 정리 전체 파이프라인, 상자 조립 등): 사전학습된 π0가 "모든 태스크에서 최대 점수의 50% 이상"을 달성했다고 보고하며, 이 태스크들은 난이도가 높아 "다른 방법으로는 아예 풀지 못했다"고 명시 — 즉 비교 베이스라인 자체가 없는 영역에서의 결과다.
- **추론 속도**: 온보드 총 73ms(이미지 인코딩+관측 처리+10회 flow 적분, §2.2) — chunk 단위 생성 덕분에 자기회귀 디코딩보다 고주파 제어에 유리하다는 주장의 근거로 제시된다.

## 4. 내 실습 연결

- 우리가 직접 재현·LoRA 파인튜닝까지 돌린 [OpenVLA](openvla.md)는 연속 7-DoF action을 **256-bin으로 이산화**해 언어 토큰처럼 자기회귀 디코딩한다(§2.2). 그 리뷰의 한계 절에서 이미 "이산화 손실은 정밀 조작에서 해상도 한계가 되고, 후속 연구들이 diffusion head·연속 action으로 옮겨간 이유"라고 적어뒀는데, π0가 바로 그 "후속 연구"의 대표 사례다 — flow matching으로 action을 연속 벡터장 회귀 문제로 되돌린 설계다.
- 방향이 흥미롭게 갈린다. [VLA 리뷰 허브](vla.md)에는 OpenVLA의 256-bin 이산화가 [DreamerV3](../world-models/dreamerv3.md)의 twohot, [MuZero](../world-models/muzero.md)의 categorical support와 같은 "연속 회귀 → 이산 분포" 계열이라고 적어뒀다. π0는 정확히 **반대 방향** — VLA 계열 안에서 다시 "이산 토큰 → 연속 회귀(flow/diffusion)"로 돌아간 사례라서, 같은 축 위에서 왕복이 일어난 셈이다.
- **구체적인 다음 실험 후보**: RT-2와 달리 π0는 `openpi`로 가중치·파인튜닝 코드가 전부 공개돼 있다. OpenVLA를 돌렸던 것과 같은 단일 GPU 로컬 환경에서, ALOHA/DROID용 공개 체크포인트로 추론을 재현하거나, 우리가 이미 세팅해 둔 [LIBERO 평가 파이프라인](../vla.md)에 π0(PyTorch/LeRobot 포트)를 붙여 OpenVLA의 실측치(spatial 80%/object 85%/goal 85%/long 45%)와 나란히 비교하는 실험이 자연스러운 다음 단계다. 총 파라미터가 3.3B로 OpenVLA(7B)보다 작다는 점도 로컬 재현 부담을 줄이는 요인이다.

## 5. 한 줄 평 / 한계

**한 줄 평.** "action을 언어 토큰처럼"이라는 RT-2/OpenVLA의 전제 자체를 뒤집은 논문. VLM의 의미 일반화는 그대로 가져오되, action 출력단만 diffusion 계열의 연속·chunk 생성으로 바꿔 고주파·양손·장기 조작이라는 이산 토큰화의 구조적 약점을 정면으로 겨냥했다. RT-2처럼 가중치를 걸어 잠그지 않고 `openpi`로 공개했다는 점도 커뮤니티 재사용성 면에서 OpenVLA의 노선을 잇는다.

**한계·의문.**
- **문헌 리뷰의 한계**: 우리가 직접 실행하지 않았으므로 위 결과는 전부 원문 서술에 의존한다 — 정확한 성공률 수치, 평가 태스크 수, 통계적 유의성 등은 미확인.
- **비교의 비대칭성**: 복합 장기 태스크에서 "다른 방법으로는 풀지 못했다"는 서술은 π0의 강점을 보여주지만 동시에 **정량적 베이스라인 비교가 불가능했다는 뜻이기도 하다** — 우위의 크기를 가늠하기 어렵다.
- **특화 모델이 이기는 경우도 있음**: 저자들 스스로 인정하듯, 일부 파인튜닝 태스크에서는 from-scratch 특화 모델이 여전히 π0를 앞선다 — "일반화 정책이 항상 최선"은 아니다.
- **자체 데이터 의존**: 7 로봇·68 태스크·1만 시간 규모의 성능은 상당 부분 Physical Intelligence의 **비공개 자체 데이터셋**에서 나온다. `openpi`로 코드·가중치는 공개됐지만, 이 규모의 자체 데이터를 그대로 재현할 수는 없다 — RT-2의 "비공개 가중치" 문제가 "비공개 데이터" 문제로 형태를 바꿔 남아 있다.
- **아키텍처 복잡도**: OpenVLA의 "VLM 인프라를 그대로 재사용"이라는 단순함 대비, π0는 별도 action expert·flow matching 학습·ODE 적분 추론이 추가된다 — 구현·디버깅 표면이 넓어진 만큼 우리가 직접 재현할 때 넘어야 할 문턱도 OpenVLA보다 높을 것으로 예상된다(미확인, 실제로 돌려봐야 확인 가능).
