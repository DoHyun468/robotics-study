# H2O (2024)

*사람 동작 → 휴머노이드: retargeting + RL 추적으로 RGB 캠 하나의 실시간 전신 텔레옵*

He, Luo, Xiao 외, *Learning Human-to-Humanoid Real-Time Whole-Body Teleoperation* (H2O), IROS 2024 (arXiv 2403.04436).

카테고리 개요: [Human Motion → Robot Data](humanmotion.md) · 전 단계: [SMPL·MANO](smpl-mano.md)

## 한 줄 요약

사람 모션 데이터(AMASS, [SMPL](smpl-mano.md) 파라미터)를 휴머노이드 몸에 맞게 **retargeting**하고(체형 최적화 + feasibility 필터로 13k→~8.5k 시퀀스), 그 동작들을 **추적하는 RL 정책**을 시뮬레이션에서 학습해 실기로 옮긴 뒤, **웹캠 1대 + 30Hz pose 추정(HybrIK)** 만으로 Unitree H1을 실시간 전신 텔레옵한다. "사람 동작 → 로봇 동작"의 세 난관(구조 차이·물리 차이·실시간)을 한 파이프라인에 묶은 대표작.

---

## 1. 문제 — 사람 동작은 왜 로봇에 바로 안 들어가나

사람 모션 캡처는 풍부하다(AMASS: SMPL 파라미터로 **40시간·13k 시퀀스**). 그런데 휴머노이드에 그대로 넣으면 세 겹으로 깨진다.

1. **구조(kinematics) 차이**: SMPL은 관절 24개·사람의 체형, H1은 **19-DoF**·다른 링크 길이. 관절 대응부터 다시 정의해야 한다.
2. **물리(dynamics) 차이**: 사람은 되는데 로봇은 못 하는 동작이 있다 — 질량 분포·토크 한계·발 크기가 다르다. 기하적으로 옮겨도 물리적으로 넘어진다.
3. **실시간 제약**: 텔레옵이라면 모션캡처 슈트 없이, 지연 없이 사람을 읽어야 한다.

> **H2O의 구도**: (1)은 **최적화 기반 retargeting**으로, (2)는 **"sim-to-data" 필터 + RL 추적 정책**으로, (3)은 **RGB pose 추정 30Hz**로 각개 격파한다.

## 2. 방법 — 세 단계

### 2.1 Retargeting — SMPL을 로봇 체형으로

- 사람과 휴머노이드 사이에 **대응 가능한 관절 12개**를 고르고, SMPL의 체형 파라미터 $\beta'$를 **휴머노이드의 골격에 가장 가깝도록 최적화**한다 — "로봇을 닮은 가상의 사람"을 먼저 만들고, 그 몸으로 모션을 재생하는 발상.

$$
\beta' = \arg\min_\beta \sum_{j \in \text{대응 12관절}} \big\| p_j^{\text{SMPL}}(\beta) - p_j^{\text{robot}} \big\|^2
$$

- 이 변환으로 AMASS 13k 시퀀스에서 **10k retargeted 시퀀스**를 얻는다.

### 2.2 "Sim-to-Data" — 물리로 데이터를 거른다

기하적으로 옮겨진 동작이 물리적으로 가능한지는 별개다. H2O의 트릭: **도메인 랜덤화 없는 특권(privileged) 모방 정책**을 시뮬레이션에서 학습시켜, 이 정책조차 추적 못 하는 동작을 데이터셋에서 제거한다.

- 결과: 10k 중 **~8.5k 시퀀스만 H1에 physically plausible**로 남는다.
- 뒤집어 읽으면 — AMASS의 15%는 이 로봇이 물리적으로 흉내 못 낸다는 실측. **데이터 정제를 시뮬레이터가 한다**는 점이 이 논문에서 가장 재사용 가치가 높은 아이디어다.

### 2.3 추적 정책 + 실시간 텔레옵

- 걸러진 동작을 추적하는 정책을 **PPO + 강한 도메인 랜덤화**(마찰·질량·PD 게인·토크 노이즈·제어 지연)로 학습 → 실기 이전(sim-to-real).
- 실시간 루프: **1080p 웹캠 → HybrIK 3D pose 추정(30Hz)** → retargeting → 정책이 19-DoF 관절 타깃 출력 → PD 제어(고유수용 감각 200Hz).
- 모션캡처 슈트·특수 장비 없이 **RGB 카메라 한 대**로 전신 텔레옵이 성립한다.

## 3. 결과 (원문 대조)

| 항목 | 값 |
|------|-----|
| 모션 데이터 | AMASS 40시간·13k 시퀀스(SMPL) → retarget 10k → **feasibility 필터 후 ~8.5k** |
| 로봇 | Unitree H1, **19-DoF**, PD 제어 |
| 실시간 인지 | HybrIK 3D pose **30Hz** (1080p 웹캠 1대) |
| 시연 태스크 | 걷기·백점프·킥·회전·손 흔들기·밀기·복싱 + 공 차기·픽앤플레이스·유모차 밀기 |

## 4. 내 실습 연결

- **retargeting은 우리 파이프라인의 "좌표 변환"의 관절체 확장판**이다. 이 사이트의 [hand-eye 캘리브레이션](../perception.md)이 "카메라 좌표 → 로봇 base 좌표"의 강체 변환(AX=XB 최적화)이었다면, H2O의 retargeting은 "사람 관절 공간 → 로봇 관절 공간"의 대응을 최적화로 푸는 문제 — 변환의 대상이 SE(3) 하나에서 관절 궤적 전체로 커졌을 뿐, "대응점을 정의하고 오차를 최소화한다"는 뼈대가 같다.
- **sim-to-data 필터**는 우리 MuJoCo 실험 방법론과 직결 — 우리가 [manipulation](../manipulation.md)에서 IK feasibility 필터로 실행 불가능한 grasp을 걸렀듯, H2O는 물리 시뮬로 실행 불가능한 모션을 거른다. 시뮬레이터의 역할이 "실행장"에서 "**데이터 검증기**"로 확장되는 사례.
- 아직 직접 실습은 아니다 — 다음 실습 후보: AMASS 일부를 MuJoCo 휴머노이드(또는 팔만)로 retarget해 관절 한계·자기충돌로 걸러지는 비율을 재보는 것(H2O의 15% 탈락률을 우리 셋업에서 재현).

## 5. 한 줄 평·한계

**한 줄 평.** "사람 동작은 데이터로 쓰기 전에 로봇의 몸과 물리로 두 번 번역해야 한다"를 파이프라인으로 완성한 논문. 특히 **시뮬레이터로 모션 데이터를 정제**하는 sim-to-data는 이후 휴머노이드 전신 제어 연구(OmniH2O·HumanPlus 등)의 표준 재료가 됐다.

**한계.**
- **상체 조작 정밀도**: 시연 태스크는 이동·전신 동작 중심 — 손끝 정밀 조작(6-DoF 정렬·미세 파지)은 이 프레임의 다음 과제다(→ 손은 [SMPL·MANO](smpl-mano.md)의 MANO 축, 조작 데이터는 [UMI](umi.md) 축이 담당).
- **선속도 추정의 외부 의존**: 실기에서 선속도 추정에 모션캡처를 보조로 사용 — 완전 자립형 상태 추정은 남은 문제.
- **retargeting은 여전히 손실 변환**: 12관절 대응 + 체형 최적화는 사람 동작의 뉘앙스(발끝·손목 세부)를 버린다 — 무엇을 보존할지가 태스크마다 달라지는 열린 설계 문제.
- **RGB 30Hz의 한계**: 빠른 동작·가림에서 pose 추정이 튀면 정책이 그대로 따라간다 — 인지 노이즈에 대한 정책의 강건성이 안전의 전제.
