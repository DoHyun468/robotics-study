# GameNGen (2024)

*확산 모델로 만든 실시간 DOOM 게임엔진*

Valevski, Leviathan, Arar, Fruchter (Google), *Diffusion Models Are Real-Time Game Engines*, 2024 (arXiv 2408.14837).

같은 갈래: [DIAMOND](diamond.md) · [Genie](genie.md) · [Cosmos](cosmos.md) · [생성·영상형 개요](generative.md)

**생성·영상형 world model**은 관측(픽셀/토큰)을 확산·자기회귀 등으로 **직접 생성**해 "플레이 가능한 세계"를 만드는 계열이다. Dreamer/MuZero처럼 제어를 위한 컴팩트 잠재를 배우는 게 목적이 아니라, **관측 자체의 생성 충실도**가 목표다. GameNGen은 이 갈래에서 "신경망이 게임 엔진 그 자체를 대체할 수 있는가"라는 질문에 가장 직접적으로 답한 사례다.

---

## 1. 문제 — 게임 엔진을 신경망으로 대체할 수 있는가

게임 엔진은 본질적으로 하나의 루프다: **입력(키 조작) → 상태 갱신(게임 로직·물리) → 렌더링(프레임)**. world model을 극한까지 밀면, 이 루프 전체를 신경망 하나로 대체할 수 있는가라는 질문에 닿는다. 즉:

$$
o_{t+1} \sim p_\theta(o_{t+1} \mid o_{t-N:t},\; a_{t-N:t})
$$

여기서 $o$는 화면 프레임, $a$는 플레이어의 키 입력, $N$은 컨텍스트 길이다. 상태 변수도, 게임 로직 코드도 없이 **과거 프레임과 행동만 보고 다음 프레임을 생성**해야 한다.

이때 두 난점이 있다.

1. **장기 일관성(auto-regressive drift)**: 생성한 프레임을 다시 입력으로 넣는 자기회귀 롤아웃에서는 작은 오차가 복리로 쌓인다. 학습 때는 항상 **진짜** 프레임을 컨텍스트로 봤는데(teacher forcing), 추론 때는 **자기가 만든** 프레임을 봐야 하는 분포 불일치가 원인이다.
2. **실시간성**: 게임은 초당 수십 프레임을 요구한다. 확산 모델의 보통 샘플링(수십 스텝의 노이즈 제거)은 너무 느리다.

GameNGen은 (1)을 **노이즈 증강**으로, (2)를 **극소 스텝 샘플링**(4-step DDIM)으로 공략한다. 대상은 고전 FPS 게임 DOOM.

## 2. 방법

### 2.1 전체 파이프라인 — 2단계

```
[1단계] RL 에이전트가 DOOM을 플레이 (PPO)
        → 플레이 궤적 (프레임, 행동) 9억 프레임 기록
[2단계] 그 데이터로 행동 조건 확산 모델 학습
        → 사람이 키보드로 조작하면 모델이 다음 프레임을 실시간 생성
```

**왜 RL 에이전트로 데이터를 모으나?** 사람 플레이 데이터를 대량으로 모으긴 비싸다. 대신 PPO 에이전트를 훈련시키며 그 **전체 학습 과정의 플레이를 전부 기록**한다(**9억 프레임**). 에이전트가 못하던 시절의 서툰 플레이까지 포함되므로, 데이터가 자연스럽게 다양한 상태를 커버한다 — "잘 하는" 데이터만 있으면 모델이 이상한 상태를 본 적이 없어 사람의 실수에 대응 못 한다.

### 2.2 확산 모델 — Stable Diffusion v1.4 개조

기반은 **Stable Diffusion v1.4**(latent diffusion). 세 가지를 바꾼다.

- **텍스트 조건 제거**: text cross-attention을 들어내고, 그 자리에 **행동 임베딩**을 넣는다(키 입력 시퀀스가 조건).
- **과거 프레임 조건화**: 과거 **64 프레임**(20 FPS 기준 약 3.2초)을 VAE 인코더 $\phi$로 잠재공간에 넣고, 노이즈 잠재에 **concat**해서 U-Net에 준다.
- 출력은 다음 프레임 하나의 잠재 → VAE 디코더로 픽셀 복원.

$$
z_{t+1} = \text{UNet}\big(\underbrace{z^{\text{noised}}}_{\text{생성 대상}};\ \underbrace{\phi(o_{t-63:t})}_{\text{과거 64프레임 잠재}},\ \underbrace{e(a_{t-63:t})}_{\text{행동 임베딩}}\big)
$$

### 2.3 노이즈 증강 — drift를 막는 핵심 트릭

자기회귀 drift의 원인은 "추론 때 보는 컨텍스트(자기 생성 프레임)가 학습 때 본 컨텍스트(진짜 프레임)보다 살짝 오염돼 있다"는 것. GameNGen의 처방은 단순하고 효과적이다:

> **학습 때부터 컨텍스트 프레임에 일부러 가우시안 노이즈를 섞는다.** 노이즈 강도는 랜덤 샘플링(최대 0.7)하고, 그 강도를 **10개 구간으로 이산화한 임베딩**으로 모델에 알려준다.

이러면 모델이 "오염된 컨텍스트에서도 깨끗한 다음 프레임을 만드는 법"을 배운다. 추론 때 자기 생성 프레임의 오차는 이 학습된 오염 분포 안에 들어오므로, 오차가 증폭되지 않고 **매 스텝 소거**된다. (같은 문제를 [DIAMOND](diamond.md)는 EDM 프레임워크 선택으로, [Dreamer](dreamer.md)류는 애초에 잠재공간 롤아웃으로 우회한다 — 계열마다 drift 대응이 다른 게 비교 포인트.)

### 2.4 마감 처리 두 가지

- **VAE 디코더 파인튜닝**: SD의 기본 디코더는 HUD(체력·탄약 표시) 같은 작은 글자를 뭉갠다. 타깃 프레임 픽셀에 대한 MSE로 **디코더만 별도 파인튜닝**해 해결.
- **4-step DDIM 샘플링**: 보통 수십 스텝인 노이즈 제거를 **4스텝**으로 줄여 **TPU-v5 한 장에서 20 FPS** 달성(단일 스텝 distillation 시 50 FPS). 흥미롭게도 이 태스크에선 4스텝으로도 품질 저하가 크지 않았다 — 과거 64프레임이라는 강한 조건이 생성의 불확실성을 크게 줄여주기 때문으로 읽을 수 있다.

## 3. 결과 (원문)

| 지표 | 값 | 해석 |
|------|-----|------|
| 다음 프레임 PSNR | **29.43** | 손실 JPEG 압축 수준의 충실도 |
| 다음 프레임 LPIPS | **0.249** | 지각적 유사도 |
| 사람 구분율(짧은 클립) | **58~60%** | 랜덤(50%)보다 약간 나은 수준 — 거의 구분 불가 |
| 실시간성 | **20 FPS** (TPU-v5 1장, 4-step) | distillation 시 50 FPS |

- 사람 평가자는 **5분짜리 자기회귀 생성 후에도** 실게임과의 구분에서 랜덤을 크게 웃돌지 못했다 — 노이즈 증강이 장기 롤아웃을 실질적으로 지탱한다는 증거.
- 의의: "충분한 데이터(9억 프레임) + 확산이면 특정 게임의 **동역학+렌더링을 통째로** 신경망이 흉내낼 수 있다"의 첫 실시간 실증.

## 4. 스터디와의 개념적 연결

- 트랙 프레이밍 그대로: "생성·영상형 = 화려하나 제어 미흡 → 로봇엔 sim/데이터 생성 용도가 먼저." GameNGen은 화질·실시간성의 상한을 보여주되, 대상이 DOOM이라는 **닫힌 이산 행동** 게임이다. 로봇의 연속·고정밀 행동 조건화는 훨씬 어려운 문제로 남는다.
- **teacher forcing↔자기회귀 불일치**는 우리가 [모방학습/VLA](../reviews/vla.md)에서 본 compounding error(behavior cloning의 분포 이탈)와 정확히 같은 구조의 문제다. 노이즈 증강은 DART/DAgger류 "학습 중 오염 주입"의 생성모델 버전으로 읽으면 연결이 선명하다.
- RL 에이전트로 데이터를 모아 생성모델을 학습시키는 구조는 "합성 데이터로 사전학습"이라는 이 사이트의 문제의식([perception](../perception.md))과 같은 축이다.

## 5. 한 줄 평·한계

**한 줄 평.** "게임 엔진을 신경망으로 대체"를 20 FPS 실시간 + 인간 구분 불가 수준으로 처음 보여준 논문. 기술적 핵심은 거창한 새 아키텍처가 아니라 **노이즈 증강 하나로 자기회귀 drift를 길들인 것** — 문제를 정확히 진단하면 처방은 단순할 수 있다는 좋은 사례다.

**한계.**
- **암기 vs 일반화**: 한 게임(DOOM)을 9억 프레임으로 학습한 결과라, 새로운 맵·규칙으로의 일반화를 보여준 게 아니다 — "세계 모델"이라기보다 "세계 하나의 모델"에 가깝다.
- **상태의 비영속성**: 화면 밖으로 나간 것(먹은 아이템, 죽인 적)이 컨텍스트 64프레임을 벗어나면 잊힌다 — 명시적 상태가 없는 구조의 본질적 한계.
- **연산 비용**: 실시간 20 FPS에 TPU급 자원 — 저사양·실시간 로봇 루프엔 그대로 부담.
- **로봇으로의 거리**: 이산 키 입력 조건화와 연속 6-DoF 행동 조건화는 난이도가 다르다. 로봇 관점 실용 경로는 [Cosmos](cosmos.md)처럼 데이터·시뮬 공급자 쪽이 먼저다.
