# 로보틱스 데이터셋 지도 — 그리고 "태스크는 누가 만드나"

[벤치 지도](index.md)가 "환경 벤치"(에이전트가 상호작용하는 시뮬)를 다뤘다면, 이 페이지는 **데이터셋**(고정된 기록) 쪽 생태계를 다룬다 — 어떤 데이터셋들이 있고, **데이터 위에 태스크·리더보드가 어떻게 생겨나며**, 수집부터 SOTA 경쟁까지의 표준 파이프라인이 무엇인지.

## 1. 핵심 질문부터 — 태스크는 세 가지 방식으로 태어난다

"데이터셋이 있으면 누가 거기에 태스크를 만드나?"의 답은 **세 패턴**으로 정리된다:

**패턴 A — 환경이 곧 태스크다 (시뮬 벤치).** [DMControl](dmcontrol.md)·[Meta-World](metaworld.md)류는 태스크가 환경 코드에 **내장**돼 있다 — 보상 함수와 성공 술어가 태스크 정의 그 자체. 데이터셋은 없거나(온라인 RL), 시연이 부속물로 딸린다([LIBERO](libero.md)).

**패턴 B — 데이터셋 제작자가 태스크까지 패키지로 출시한다.** 인지 계열의 표준. KITTI·nuScenes·[GraspNet-1B](../reviews/graspnet.md)는 데이터만 공개한 게 아니라 **태스크 정의 + 지표 + train/test 분할 + (숨겨진 테스트 GT의) 평가 서버 + 리더보드**를 한 묶음으로 냈다. 이 묶음 전체가 "벤치마크"라는 말의 원래 뜻이다.

**패턴 C — 제3자가 남의 데이터/환경 위에 새 프로토콜을 얹는다.** Atari 100k는 남의 환경(ALE)에 "10만 스텝 예산"이라는 **프로토콜만** 새로 정의해 샘플효율 벤치를 만들었고, D4RL은 기존 환경들에서 정책들을 돌려 **기록을 데이터셋화**해 오프라인 RL 벤치를 만들었으며, Open X-Embodiment는 **21개 기관의 기존 데이터셋들을 표준 포맷으로 통합**해 사전학습 자원을 만들었다. 즉 태스크를 만드는 주체는 데이터 주인만이 아니다 — **프로토콜을 정의하고 커뮤니티가 받아들이면 그게 벤치가 된다.**

세 패턴을 관통하는 공식 — **태스크의 4요소**:

> 태스크 = **입력 정의** + **출력 정의** + **지표(metric)** + **분할(train/val/test)**

이 넷을 정하는 사람이 태스크를 만드는 사람이다. 같은 데이터라도 4요소를 다르게 정하면 다른 태스크가 된다(KITTI 한 벌 위에 stereo·flow·odometry·detection·tracking이 **각각의 태스크**로 존재하는 이유).

## 2. 표준 파이프라인 — 수집에서 SOTA 사이클까지

**인지 계열(패턴 B)의 정석 파이프라인** — KITTI(2012)가 원형을 만들었고 nuScenes가 계승:

```
① 수집     센서 리그 설계(카메라·LiDAR·IMU) + 캘리브레이션·동기화  ← av_stack §2.1의 그 정렬
② 정제     시퀀스 선별·익명화(번호판/얼굴)·포맷 표준화
③ 어노테이션  GT 제작 — 사람 라벨링(3D 박스·세그) / 센서 GT(LiDAR→depth GT)
             / 자동 계산(GraspNet-1B: 물체 모델 위 해석적 grasp 판정 11억 개)
④ 태스크 정의  4요소 확정 + 테스트셋 GT는 비공개로 보관
⑤ 공개     데이터 + 개발킷 + 평가 서버 + 리더보드 + 라이선스
⑥ 사이클    커뮤니티가 학습→제출→순위 경쟁 → 논문들이 이 지표로 SOTA 주장
⑦ 포화·교체  지표가 천장에 닿으면 차세대 데이터셋이 등판 (KITTI → nuScenes → 대규모 후속)
```

읽어둘 설계 포인트 세 가지:

- **왜 테스트 GT를 숨기나** — 공개하면 테스트셋에 과적합한 SOTA가 양산된다. 평가 서버 + 제출 횟수 제한이 이 생태계의 심판 장치다(KITTI가 정착시킨 관행).
- **지표 설계가 연구 방향을 정한다** — nuScenes가 AP 하나가 아니라 속도·크기·방향 오차까지 묶은 종합 지표(NDS)를 만든 건, "박스만 잘 치는" 최적화를 막으려는 의도적 설계다. 지표는 중립적 측정이 아니라 **커뮤니티를 조향하는 손잡이**다.
- **라이선스가 산업 사용을 가른다** — KITTI는 CC BY-NC-SA(비상업) — 연구엔 표준이지만 제품 학습엔 못 쓴다. 데이터셋 표에서 라이선스 열을 그냥 지나치면 안 되는 이유.

**로봇 학습 계열(시연 데이터셋)의 변형** — 여기가 인지 계열과 결정적으로 다르다:

```
수집(텔레옵/핸드헬드) → 표준 포맷(RLDS 등) → 사전학습/파인튜닝(데이터셋의 역할은 여기까지)
                                                    ↓
                              채점은 별도의 장소에서: 시뮬 벤치(LIBERO) 또는 실로봇 평가
```

인지 계열은 **같은 데이터셋 안에서** train/test를 나눠 채점하지만, 로봇 조작은 "정책이 좋은가"를 기록만으로 채점할 수 없다(같은 상태를 재현할 수 없으므로). 그래서 **학습은 데이터셋에서, 채점은 환경에서**로 생태계가 이원화된다 — [OpenVLA](../reviews/openvla.md)가 OXE로 사전학습하고 [LIBERO](libero.md)에서 채점받는 구조가 그 표준형이다. 실로봇 채점은 재현성이 약해(로봇·조명·물체가 랩마다 다름) 아직 "평가 서버" 같은 심판 장치가 없다는 것이 이 분야의 공개된 약점이다.

## 3. 카탈로그 — 계열별 대표 데이터셋

각 표의 "태스크 정의자" 열이 §1의 질문에 대한 사례별 답이다. 수치는 원문 대조.

### 3.1 로봇 시연 (조작 정책 학습용)

| 데이터셋 | 규모 (원문) | 내용 | 태스크 정의자 |
|---|---|---|---|
| **Open X-Embodiment** (2023) | 로봇 **22종**·**21개 기관**·**527 스킬(160,266 태스크)**, 궤적 ~100만 규모 | 기존 랩별 데이터셋들을 RLDS 표준 포맷으로 **통합** | 패턴 C — 통합 주체는 포맷·스킬 분류만 정의, 채점은 각자의 벤치/실기에서 |
| **DROID** (2024) | **76k 궤적·350시간·564 씬·84 태스크**, 수집자 50명·12개월 | 표준화된 Franka 셋업으로 북미·아시아·유럽에서 수집 — **씬 다양성**이 목적 | 패턴 C — 학습용 공급. 하드웨어 재현 가이드까지 공개해 "수집 리그" 자체를 표준화 |
| **BridgeData V2** (2023) | **60,096 궤적·24 환경** | 저가 로봇(WidowX급) 탁상 조작, 목표 이미지·언어 조건 | 패턴 C — 학습용. 채점은 같은 로봇을 가진 랩의 실기 평가 |
| **LIBERO 시연** (2023) | 130 태스크 × 태스크당 시연 | 시뮬 텔레옵 시연 — 벤치에 부속 | **패턴 A+B 겸용** — 환경·시연·채점(BDDL)을 한 묶음으로 |

이 계열의 공통점: **지표가 없다.** 데이터셋 자체는 채점하지 않고, 무엇이 좋은 정책인지는 하류의 벤치·실기가 정한다 — "데이터셋 = 원료, 벤치 = 저울"의 분업.

### 3.2 Grasp · 물체 에셋

| 데이터셋 | 규모 (원문) | 태스크 정의자 |
|---|---|---|
| **[GraspNet-1B](../reviews/graspnet.md)** (2020) | 190 씬·97,280 RGB-D·**grasp 라벨 11억+**(해석적 자동 생성) | 패턴 B의 교과서 — 데이터 + grasp 평가 프로토콜 + 리더보드를 함께 출시. 이후 5년간 [후속 모델들](../grasp_sota.md)이 이 벤치에서 경쟁 |

|---|---|---|

### 3.4 자율주행 인지 ([av_stack](../av_stack.md)의 채점장)

| 데이터셋 | 규모 (원문) | 태스크 정의자 |
|---|---|---|
| **KITTI** (2012) | 스테레오(흑백+컬러)·Velodyne LiDAR·GPS, 차량 탑재(칼스루에) | 패턴 B의 **원조** — stereo·flow·odometry·3D detection·tracking·depth·segmentation 각각을 별도 태스크로 정의, 숨긴 테스트 GT + 평가 서버 + 리더보드. 라이선스 CC BY-NC-SA(비상업) |
| **nuScenes** (2019) | **1000 씬×20초**, 카메라 6·레이더 5·LiDAR 1(360°), **23클래스 3D 박스**(KITTI의 7배 주석) | 패턴 B — detection·tracking(·prediction) 태스크 + 종합 지표(NDS) 설계. "멀티센서 360° 리그"가 표준이 된 계기 |

이 계열이야말로 [av_stack](../av_stack.md)에서 유도한 검출·추적·융합이 **실제로 채점되는 곳**이다 — 센서 리그·캘리브·동기화(§2.1)가 데이터셋 제작 단계의 ①②에 그대로 들어있다는 점이 "기하가 데이터 품질의 상한"이라는 우리 논지의 산업 판이다.

### 3.5 오프라인 RL

| 데이터셋 | 내용 | 태스크 정의자 |
|---|---|---|
| **D4RL** | 기존 환경(locomotion 등)에서 다양한 품질의 정책 기록(random/medium/expert 조합) | 패턴 C의 교과서 — 환경도 데이터도 기존 것, **"이 기록만으로 배워라"라는 프로토콜**이 새 기여. [DT](../world-models/decision-transformer.md)·[TT](../world-models/trajectory-transformer.md)의 채점장 |

## 4. 우리 트랙과의 연결

- **소비자로서**: [OpenVLA 재현](../vla.md)은 OXE(97만 궤적 큐레이션)로 사전학습된 모델을 LIBERO에서 채점한 것 — §2의 이원화 파이프라인을 끝에서 끝까지 밟은 실측이다. [grasp 6모델 A/B](../grasp_sota.md)는 GraspNet-1B 계보의 모델들을 **우리 자체 환경**에서 재채점한 것 — "벤치 점수 ≠ 우리 씬 점수"라는 도메인갭을 실측했다.
- **제작자 관점으로**: 우리 [perception 트랙](../perception.md)의 캘리브→동기화→GT 렌더→오차 예산 루프는 §2 파이프라인의 ①~③을 소규모로 직접 돌린 셈이다. [UMI](../reviews/umi.md)의 "SLAM 오차 6.1mm = 라벨 노이즈"는 ③의 품질이 곧 데이터셋 품질이라는 명제의 산업 사례.
- **다음 실습 후보**: KITTI odometry 시퀀스에 우리 [SLAM 트랙](../slam.md)의 VO/pose-graph를 태워 공식 지표(ATE/RPE)로 채점해보기 — "남의 벤치에 제출 가능한 형식으로 결과를 내는" 파이프라인 경험이 목적.
